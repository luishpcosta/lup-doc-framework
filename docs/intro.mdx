# Introdução

## Resumo executivo

O framework híbrido entrega, para cada papel do ciclo de desenvolvimento, um agente orquestrador equipado com as habilidades certas — não uma lista de ferramentas para chamar manualmente. Profissionais de produto usam esse agente para conduzir a análise de negócio, líderes técnicos para a análise técnica, e desenvolvedores para especializar a implementação. Cada papel recebe um resultado padronizado, pronto para dar sequência ao ciclo — não um ponto de partida solto. A aposta não é mais uma ferramenta de IA: é orquestração especializada por função, pavimentando o caminho para automações futuras.

## O Problema

Existem dezenas de ferramentas agênticas disponíveis hoje — mas falta um caminho prático de como especializá-las por função dentro de um ciclo de desenvolvimento coerente. Cada pessoa adota a que prefere, para a tarefa que tem na frente, sem que o resultado de uma etapa se conecte à próxima.

## A Solução

O framework híbrido não é uma lista de agentes para cada pessoa chamar manualmente, um a um — é um agente orquestrador, equipado com as habilidades certas para cada papel, que conduz o trabalho e entrega um resultado padronizado para dar sequência ao ciclo:

- **Profissionais de produto** usam o agente orquestrador para conduzir a análise de negócio.
- **Líderes técnicos** usam o agente orquestrador para conduzir a análise técnica.
- **Desenvolvedores** usam agentes especializados na implementação.

Cada papel entrega ao próximo um resultado padronizado, pronto para uso — a IA não é a mesma ferramenta genérica passando de mão em mão, ela é orquestrada e especializada para a etapa em que está.

## O que torna isto diferente

O caminho óbvio seria dar a mesma ferramenta genérica de IA para todo mundo e deixar cada pessoa chamar agentes manualmente, um a um, conforme a necessidade. O framework aposta no oposto: um agente orquestrador, com habilidades especializadas por função — o profissional de produto usa IA para análise de negócio, o líder técnico para análise técnica, o desenvolvedor para implementação — entregando um resultado padronizado que vira insumo direto da próxima etapa, em vez de uma saída solta que precisa ser reinterpretada manualmente.

## Quem isto serve

- **Profissionais de produto** — conduzem a análise de negócio com apoio do agente orquestrador.
- **Líderes técnicos** — conduzem a análise técnica com apoio do agente orquestrador.
- **Desenvolvedores** — especializam a IA na implementação: do pipeline de execução a tarefas do dia a dia, como revisão de código assistida, testes gerados por agente e apoio a debugging.

## Critérios de sucesso

- Cada papel usa agentes especializados na própria etapa — não só IA genérica de produtividade pessoal.
- O que sai da análise de negócio chega à análise técnica sem reconstrução manual, e daí até o código.
- Um squad novo consegue adotar o modelo sem depender de treinamento informal.

## Escopo

**No escopo:** a especialização agêntica por papel (produto, técnica, desenvolvimento) e como ela se orquestra dentro do mesmo ciclo de desenvolvimento.

**Fora do escopo:** o detalhamento dos artefatos e do pipeline técnico que sustentam essa especialização — isso vive na página inicial e nos guias práticos, referenciados abaixo.

## Visão

O ponto de partida são três papéis — produto, técnica, desenvolvimento. A mesma lógica de orquestração especializada pode se estender a outros papéis do ciclo — QA, design, suporte — conforme o modelo se prova em produção. O output padronizado de cada etapa também pavimenta o caminho para automações futuras: quanto mais previsível a entrega de um papel, mais fácil conectar a próxima etapa sem intervenção manual.
